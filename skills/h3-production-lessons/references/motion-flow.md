# 运动与流畅（F-）

动画"中等、没节奏、不连贯"时先读这里。量化口径：`h3_timecode` 节奏预检（按写入时间码）、`h3_align` 成片读数（按画面，10-01 起是 `bridge/h3_rhythm.py` 的像素口径）。深海 13 支原片在像素口径下：事件 17.1–45.2 个/分、运动占比 28–81%、静止中位 0.54–1.94 s、墨量中位 5–50%、色面 p90 10–56%（代码 `bridge/h3_storyboard.py` DEFAULT_STYLE 注释，10-01）。

**旧口径**：10-01 之前的读数和研发线 `视频分析/scripts/analyze_reference.py` 的节奏数是 ffmpeg scene_score，它把平滑运动读成没动（同一期 scene 口径 2%、像素口径 17%，`h3_rhythm.py` 头注）；深海原片在旧口径下是事件 14–33 个/分（中位 20）、运动占比 12–29%、静止中位 0.9–2.7 s、色面 3–17%。旧读数只和旧区间比，不和现在的 `target_*` 比。

### F-001 几条"合理"的节奏规则叠在一起，把事件压到原片的四分之一（复现）
- 症状：画框 v1 / v2 成片 7.2 / 5.2 个/分、运动占比 2% / 1%、静止中位 6.3 / 7.0 s、最长静止 16.9 / 27.6 s（scene_score 旧口径，像素口径未复量）；用户评价"节奏、连贯流畅感、配色、元素都很中等"。
- 失败做法：同时执行"每段事件少于句数""每段至少三分之一句静止""事件间隔 >1.2 s""每段 ≤6 个时间码"，加上段 ≥2 首事件 ≥1.2 s、段尾留 ≥0.8 s 的死画面。
- 有效做法：用**节奏预算**代替"事件少于句数"——按本期 `target_events_per_min` 排事件（当时按旧口径 14 排；现在代码缺省 17.0，像素口径），静止句按**整片**算、不逐段凑（这两期按深海的约三分之一）；事件可落在句中关键词上。v3 按此排，预检 11.7 → 实测约 13 个/分，静止中位 2.8 s（旧口径；v3 草稿的像素口径复量见 F-007）。
- 原因：配音约 28 句/分（比原片慢），18 个/分 ≈ 每句 0.65 个事件；"事件 < 句数"再叠静止配额就到 5–7 个/分。
- 适用：深海暗底 / 亮纸两期；其他风格按其 `target_*` 键。
- 证据：画框 v1、v2 768（09-30），v3 草稿（10-01）；会话 10-01。
- 已升级 → `h3-storyboard-writing` §0「整片节奏按预算写」、§4（静止按整片）、§6（节奏目标键）；`h3_lint` 已改为只数事件起点（`include_by=False`），`finishing by` 不再算事件。

### F-002 画框同稿对照：瞬现与过程混用（复现记录；已测范围见下）
- 对照：同稿两段草稿，A 全瞬现、B 全滑动（每拍 until）。
- 结果：B 读数反而更低（10.8 vs 13.5 个/分，运动 2.1% vs 3.2%；scene_score 旧口径，它把平滑运动读成没动，B 的劣势可能被放大，待像素口径复量），填色出刷子笔触（P-011），段 1 首事件晚 0.53 s；但 B 的画框拉宽有过程、好看。结论不只靠读数：刷子笔触和首事件晚两条是画面证据。
- 有效写法：motion_rule 写"没给结束点的是四分之一秒内的瞬变；给了结束点的匀速到点即停、不回弹"；拉宽、垂下、变形这类 hero 拍给 until，其余瞬现。
- 证据：画框 v3 / 实验_画框v3_瞬现对照 草稿段 1–2（10-01）。详细数值见 T-004。
- 适用边界：亮纸图形画框、草稿的这组对照；旧 scene_score 数值未像素复量。混合写法是本组的可控选择，不据此把所有风格/所有动作设为默认瞬现，过程承担内容时仍需保住可见过程。
- 已升级 → `h3-storyboard-writing` §6 动作写法三选一。

### F-003 细线慢慢动，帧差量不到，眼睛也觉得"没动"（复现）
- 症状：水位线、描线、猫的线稿、慢滑的细框，`h3_align` 报"未检到动作"，成片读数不涨。
- 有效做法：要被"看见在动"的拍用**块面**：填色、实线↔虚线、整块形变、厚重元素落位/滑入（画框落下、尾巴甩下、手机变胶片框）。运动占比靠变化的面积，不靠把细线动作拉长。
- 证据：E2E 冰为什么浮（09-27）、v3 草稿（10-01）。
- 已升级 → `h3-storyboard-writing` §0「关键动作用块面」。

### F-004 刻意的长停要算进预算，别被中位数逼着加小动作（单次）
- 现象：v3 的"危险前一拍"长停把静止中位顶到目标附近；想加小事件压中位会破坏留白。
- 做法（未单独出片验证）：长停每章最多一次、写在稿里标"间"；中位数超标先删别处的冗余静止，不在长停里塞动作。快门那类"静止本身是内容"的拍保留。
- 证据：画框 v3 草稿（10-01）。

### F-005 段界是流畅感的主要断点（单次，待复核）
- 现象：每个段界有一段"死画面"（上一段段尾留白 + 下一段首事件 ≥1.2 s），段越多越碎。
- 做法（未单独出片验证）：段尽量 12–15 s，减少段界；段 ≥2 首事件按 T-003 调 `continuation_head_s`，不另加段尾留白。长段后半风险见 C-002。
- 证据：画框 v2 / v3 分段统计（10-01，会话分析，未单独 A/B）。

### F-006 创意 skill 的起停工艺被产线"瞬现"一句话覆盖（单次）
- 现象：`creative-animation-treatment` 写的滑入回弹、描线加速急停、A 直接变 B，到了提示词只剩 `appears instantly`，画面全是开关式出现/消失。
- 做法：编译时（`h3-prompt-writing` 创意编译）把 hero 动作的起停写成 until + 终态，不让默认 motion_rule 吞掉；非 hero 拍才用瞬现。
- 证据：画框 v1/v2 对比 treatment 原文（10-01 会话分析）。
- 回流：已写进 `h3-prompt-writing` creative-compile §7.2（每个事件写成锚 + 包络 + 反应 + 保持）、`creative-animation-treatment` world-class.md §五 A 线第 7、9 条（混合写法；包络写进同一个事件从句）。成熟度仍是单次。

### F-007 读数接近目标、对齐也过，用户仍判"元素极简、动画中等"：差在世界，不在动作数（单次）
- 症状：画框 v3 四段草稿（10-01）用户原话"元素是极其简单的图形""动画还是中等感觉"。抽帧：奶油纸面上一根线、两只剪影小鸟、角落一个灰三角、一个框、一块黄；除了那块黄框，画面大半是空纸；所有变化都是出现 / 填色 / 变虚线；唯一有生命的是一条猫尾巴。
- 读数（10-01 用 `h3_rhythm` 像素口径复量，目标见 `h3-storyboard-writing` §6）：第二轮 18.2 个/分（目标 17，过）、墨量中位 27%（5%，过）、色面 p90 23%（10%，过）、运动占比 22%（25%，差一点）、静止中位 2.2 s（2.0 s，差一点）；第一轮 19.5 个/分、运动 15%、色面 37%。密度、墨量、色面都过线，观感仍不过——墨量大半是那块黄框撑起来的，不是世界。
- 有效做法：未出片验证。方向——档位按知识住在哪里定（锁定风格自己的档位规则；没有就按 `creative-animation-treatment` Step 2b），本期风格块满配写世界（`h3-prompt-writing` creative-compile §7），交稿前过 `creative-animation-treatment` 世界级门槛（world-class.md §三）。新写法的三处风险（活层、视差横移、R3 档位块）列在 `creative-animation-treatment` transitions.md §7 待测 T8–T10，测完记到这里。
- 原因：`h3_align` 成片读数量的是"动了多少、多大面积、多少颜色"，量不到"画面里有没有世界"；墨量、色面目标都是下限，过了不等于好。
- 导演复核：对照本期“因果骨架、不可丢的动作证据、动作设计表”，检查变化是否承担概念/情绪、hero 动作是否有完整过程、结果是否被下一拍继承。此为设计审查建议，尚未证明加世界/加元素能修好本期，不升级为“越丰富越好”的通用结论。
- 证据：画框 v3 草稿段 1–4（10-01 10:09–13:11，`H3分镜台\设计师深海\04_电影视听语言\第001期_画框里是故事框外是选择_短版v3\试片\`）；用户反馈与 Kiro 抽帧（会话 10-01）。
- 回流（10-01）：已写进 `creative-animation-treatment`（world-class.md 全文；SKILL Step 2b、7e）、`h3-prompt-writing`（creative-compile §7 满配八槽）、`h3-storyboard-writing`（§0「世界写在风格块里」、§6 R3–R5 写法），以及用到它的风格与选题 skill（档位规则、领域档位表）。
